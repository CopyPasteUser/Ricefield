# RiceField 1.0 — final desktop polish

This is the **ordered last-mile polish plan**, not a replacement for the
[safety roadmap](../ROADMAP.md), [candidate evidence](1.0-STATUS.md) or
[physical owner acceptance](OWNER-ACCEPTANCE-1.0.md). A checked software
subtask does not certify X11, Wayland, Synology or hardware compatibility.
Keep Thunar/Nemo installed until acceptance; do not tag stable 1.0 early.

## 1. Drag/drop and clipboard confidence — in progress

- [x] Resolve external drops against the actual **local** folder/tab/split pane
  under the pointer. Never write to a remote tab's hidden local fallback path;
  only fall back to the focused local folder if the backend supplies **no**
  pointer position. Block dropping behind active dialogs.
- [x] Show external drag-hover target and item count, and bound/validate the
  source list (including repeated paths, root paths and unsupported payloads).
  Keep native drops and internal drag operations on the same no-overwrite
  transfer worker; show failures instead of silently discarding them.
- [ ] Complete desktop-native **outbound** drag initiation under X11/Wayland.
  Current eframe 0.37 / winit 0.30.13 cannot initiate outbound data sources;
  the explicit `ripdrag`/`dragon` action is a supported optional helper, not
  equivalent to dragging a file tile directly into another app. Investigate
  upstream API support or a separately maintained bridge before claiming it.
- [ ] Owner verifies file/folder drag in both directions among Thunar, desktop,
  browser, RiceField tabs and split panes under X11 and Wayland (including
  missing compositor support), with clipboard Cut/Copy/Paste as keyboard fallback.

**Gate:** never claim native Wayland or direct tile-to-app drag-out until
observed on physical hardware. No remote writes through a local path alias.

## 2. Linux application and device handoff — not started

- [ ] Exercise FileManager1 and default-manager registration, folder launch
  from other apps, Open With/system chooser, MIME associations and focus.
- [ ] Exercise USB mount/unlock/lock/eject, busy/error states, Polkit and
  portal fallback; regression-test available deterministic paths.
- [ ] Verify all seven shells, compact widths and keyboard alternatives use
  the same action dispatch and disabled-state contract.

**Gate:** a common Linux desktop workflow never depends on a fake control,
steals focus, or bypasses the verified filesystem worker.

## 3. Operational clarity, language and accessibility — not started

- [ ] Audit keyboard traversal, Escape, focus restoration, selection and
  screen-reader labels across the seven shells.
- [ ] Complete German/English core-dialog messages and explain unavailable
  remote operations, partial transfers and recovery without implying success.
- [ ] Measure startup, idle CPU/RAM and 100k-item browse responsiveness on
  real older hardware, addressing observed regressions only.

**Gate:** no misleading success, hidden required action or blocking GUI path.

## 4. Final candidate freeze and owner acceptance — not started

- [ ] Fix release blockers from Steps 1–3 and the open remote-write safety
  matrix, then re-run Rust checks, native GUI smoke and SMB fixtures.
- [ ] Verify Mint/ThinkPad X11 and Wayland, 4 GB hardware, Synology test share,
  USB/LUKS, loss/reconnect and archive/Desktop Trash interoperability with
  disposable files; record each result in the owner acceptance matrix.
- [ ] Freeze a source SHA, test install/update/rollback, update screenshots,
  changelog and checksums; publish stable `v1.0.0` **only after sign-off**.

**Explicit 1.0 limitation:** direct remote rename, delete, directory or
multi-file writes and MTP writes are intentionally disabled under the
[remote write contract](REMOTE-1.0-SCOPE.md) pending backend safety evidence.
Expanding that contract is separate feature development, not a polish checkbox.
